# GL-kun クイックスタート（プライベートPCで試作品を動かす）

> この手順書は、本リポジトリの**試作品（GL-kun）を自分のPCで動かして試す**ためのものです。
> 会社の機密文書は使わず、**ダミーの設計書テキスト**で動作確認することをおすすめします。
>
> **今の試作品でできること**：ドキュメントを**テキストで貼り付けて**レビュー／3種類（基本設計書・試験項目書・試験結果報告書）
> ※ Word/Excel/PowerPoint のフォルダ取り込み・要件定義書/提案書・旧版突合は「要件定義書」に記載した将来仕様で、まだ実装されていません。

---

## 1. 必要なもの（3つ）

| # | 必要なもの | 入手方法 |
|---|---|---|
| 1 | **Python 3.10 以上** | https://www.python.org/downloads/ からインストール（Windowsはインストール時に「Add Python to PATH」にチェック） |
| 2 | **Anthropic の API キー** | https://console.anthropic.com/ に登録 → API Keys で発行（`sk-ant-...`）。**従量課金**（使った分だけ） |
| 3 | **インターネット接続** | レビュー実行時に AI API を呼び出すため |

> 確認コマンド（どちらかで 3.10 以上と表示されればOK）：`python --version` または `python3 --version`

## 2. コードを入手する

**方法A：Git でクローン（推奨）**
```bash
git clone <このリポジトリのURL>
cd GL-kun
```

**方法B：ZIPでダウンロード**
GitHub の「Code」→「Download ZIP」で取得し、解凍してそのフォルダに入る。

## 3. セットアップ

### Windows（PowerShell / コマンドプロンプト）
```bat
cd GL-kun\backend

REM 仮想環境を作って有効化
python -m venv .venv
.venv\Scripts\activate

REM 依存ライブラリをインストール
pip install -r requirements.txt

REM APIキー設定ファイルを作成
copy .env.example .env
REM .env をメモ帳などで開き、次の行を書き換える:
REM   ANTHROPIC_API_KEY=sk-ant-ここに自分のキー
```

### Mac / Linux（ターミナル）
```bash
cd GL-kun/backend

# 仮想環境を作って有効化
python3 -m venv .venv
source .venv/bin/activate

# 依存ライブラリをインストール
pip install -r requirements.txt

# APIキー設定ファイルを作成
cp .env.example .env
# .env を開き、次の行を書き換える:
#   ANTHROPIC_API_KEY=sk-ant-ここに自分のキー
```

> `.env` は `.gitignore` 済みなので、APIキーが誤ってコミットされる心配はありません。

---

## 4. 起動する

```bash
python main.py
```

`Uvicorn running on http://0.0.0.0:8000` のような表示が出たら成功です。
ブラウザで **http://localhost:8000** を開いてください。

停止するときは、起動した画面で `Ctrl + C` を押します。

---

## 5. 使ってみる

1. **「プロジェクト設定」タブ**（任意・初回のみ）
   - プロジェクト概要／固有ルール／最近の課題／追加チェックリストを入力して「保存」。
   - ここに入れた内容がレビューの観点に反映されます。空でもレビューはできます。

2. **「レビュー実行」タブ**
   - ドキュメント種別を選ぶ（基本設計書 / 試験項目書 / 試験結果報告書）
   - 本文をテキストで貼り付ける（ダミーでOK）
   - 「レビュー開始」を押す
   - 数十秒で「総合評価（A〜D）／観点別レビュー／重要指摘／改善提案／総評」がリアルタイム表示されます。

3. 結果は「コピー」できます。

### 試しに使えるダミー本文（コピペ用）
```
文書番号: BD-001  タイトル: 受発注システム 基本設計書  版数: 1.0
1. 目的: 受発注業務を電子化する。
2. 機能一覧: 受注登録、在庫引当、出荷指示。
3. データ設計: 受注テーブル（受注ID、顧客ID、金額）。
4. 非機能: 性能は適宜対応する。
```
※ わざと曖昧な表現（「適宜」）や記載漏れを入れてあります。AIがどう指摘するか確認できます。

## 6. うまくいかないときは

| 症状 | 対処 |
|---|---|
| `python が見つからない` | Python を再インストール（Windowsは「Add to PATH」にチェック）。`py -3` でも試す |
| `ANTHROPIC_API_KEYが設定されていません` | `backend/.env` にキーを正しく書いたか確認。書いたら `python main.py` を再起動 |
| `pip install` でエラー | `python -m pip install --upgrade pip` を実行してから再度インストール |
| ポート8000が使用中 | 他のアプリを止めるか、`backend/main.py` 末尾の `port=8000` を `8001` 等に変更 |
| レビューがエラーになる | APIキーの有効性・残高、ネット接続を確認。`console.anthropic.com` で課金設定済みか確認 |

---

## 7. 費用について

- レビュー1回ごとに、貼り付けた文書量に応じた**従量課金**が発生します（少量のテキストなら数円程度が目安）。
- 静的なガイドライン部分は**プロンプトキャッシュ**で再利用され、2回目以降のコストが下がる設計です。
- 使い終わったら、ターミナルで `Ctrl + C` を押してサーバーを停止すれば課金は発生しません（起動中でも、レビューを実行しなければ課金されません）。
